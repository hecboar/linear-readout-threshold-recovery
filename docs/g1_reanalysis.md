# G1 reanalysis — geometry versus readout suboptimality

Generated by `scripts/reanalyse_g1.py` from `results/e5_weights/`. The committed
`results/e5/` carries no weights, so this needs its own run; the reproduction check
below states how closely that run matches the published diagnostics.

The published ratio factors exactly into

    W(G, Phi) / W_global  =  R_geom x R_readout,
    R_geom    = W_*(Phi) / W_global    (this code's geometry vs the best possible)
    R_readout = W(G, Phi) / W_*(Phi)   (this readout vs the best for this code)

`R_geom` is exactly the leverage heterogeneity of the code; `R_readout = 1` means the
readout is the code-specific optimum, which the calibrated pseudoinverse always is.

## Reproduction check

- matched 25 of 25 runs against the committed results
- worst relative deviation in the Welch-referenced ratio: **7.97e-10**
- the re-run reproduces the published diagnostics to 8e-10 relative, so the reanalysis below describes the same models the manuscript reports. The residual is not solver noise: E5 stores weights as `float32` to keep the archive small, and casting them back to `float64` here perturbs the ratio at about that size. Exact agreement would need `float64` storage, which doubles the weight archive for a difference nine orders of magnitude below anything reported.

One consistency check worth naming: `R_readout(wout)` for the random control is
exactly 1 because `random_code_baseline` sets `W_out = pinv(Phi)`, so its "own
decoder" *is* the code-specific optimum by construction. That is audit finding P1
resurfacing, and it confirms the decomposition behaves as it should.

`R_readout(pinv) = 1` by construction in every cell -- the calibrated pseudoinverse
*is* the code-specific optimum, which is the content of G1 and is asserted in the
tests. That is also why the published 'within a few parts in a thousand of the floor'
number is a statement about the code's leverage profile and not about the decoder:
under the pseudoinverse the readout term is exactly one, so the whole ratio is
`R_geom`.

### What this does and does not license

- The split is exact and needs no new assumption; it is arithmetic on G1.
- It reinterprets an existing number rather than adding evidence. Five seeds at one
  width remain five seeds at one width, and nothing here changes that.
- `R_readout(wout)` is the quantity worth carrying into the scaled campaign: it asks
  whether training produced a decoder that is good *for the code it built*, which is
  a different question from whether the code is good.
- No claim is made about the *optimisation* being ours. It is the Capon/MVDR
  beamformer with the frame operator in place of the covariance; see the novelty
  audit.
